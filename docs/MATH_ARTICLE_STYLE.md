# 数学記事の記法と表示規約

数学記事は、本文の意味をMarkdownで保ち、表示上のカード化や折りたたみは学習サイトの共通レンダラーに任せる。見た目だけを再現するためのHTMLやCSSを記事ごとに追加しない。

## 数式

- インライン数式は`$...$`、別行数式は`$$...$$`を使う。
- 数式の表示はMathJax（SVG）を正規の出力とする。KaTeXのHTMLを記事本文へ直接貼らない。
- 長い別行数式は、本文の幅を押し広げず式単位で横スクロールできる状態を維持する。

## 定義・命題・定理・補題・例

- 本文冒頭の`定義`、`命題`、`定理`、`補題`、`系`、`例`はレンダラーが対応するクラスへ変換する。
- 定義枠内の強調はMarkdownの`**強調**`、または`<strong>強調</strong>`を使う。`font-weight`を通常文字へ戻すCSSを追加しない。
- 新しく定義する語（多くは`用語(english)という`の形）は強調する。**英語の併記まで強調に含める**（`用語(english)`全体）。強調するのは用語そのものだけで、直前の助詞や修飾節は含めない。
- 英語の括弧書きを含む強調は`<strong>用語(english)</strong>`と書く。`**用語(english)**`はCommonMarkの flanking 規則で閉じ側が成立せず、本文に`**`が出てしまう。
- 番号付き条件・手順はMarkdownの`1.`形式で記述し、HTMLでは`<ol>`を使う。番号が不要な列挙だけを`-`形式の`<ul>`にする。
- 定義・命題・証明が「以下が成り立つ」「以下の条件は同値である」のように列挙を導く場合は必ず`1.`形式にする。本文が「2. より」のように番号で参照するため、`-`形式にすると参照先が消える。
- `.example`は意味上のグループであり、命題や定理のような外枠・背景・影を付けない。例タイトルだけをラベルとして表示する。
- 例のラベルは定義・命題と同じ塊のラベルとして単独の行に置き、本文を次の行から始める。枠が無いため、枠の上辺へ重ねる負のマージンは使わない。本文がラベルの右へ回り込む`inline-block`にしない。
- 数学カードのタイトルや本文の句読点を記事ごとに独自CSSで調整しない。句点の正規化は共通レンダラーの規則に従う。

## 証明とfolding

- 証明は本文の`証明.`または`証明。`からレンダラーが`details.proof-details.folding`へ変換する。
- 証明の終わりは`◻`（`□`、`∎`も可）で示す。レンダラーは終止記号の段落までを証明枠に入れ、その後の本文は枠の外に残す。終止記号を書き忘れると、次の見出しまでの解説文が証明枠へ入り込む。
- 本文の`補足 …`はレンダラーが`details.supp-details`へ変換する。記事ごとに`<div class="supp">`を書き足す必要はない。補足は次の見出し・定理枠・証明までを中身にする。
- 証明一括ボタンは、閉じているとき`▶ 証明を展開`、開いているとき`▼ 証明を閉じる`とする。矢印は文字列の`>`ではなく、`▶`と`▼`を使う。
- 個々の折りたたみ（`証明.`を含む）の矢印も`▶`と`▼`の文字にする。CSSの枠線で山形を描かない。位置は`top: 50%`と`translateY(-50%)`で縦中央に置き、`top`を固定値にしない。
- `details.supp-details`は下辺の枠線を持たない。中身の`.supp-details-inner`も`border-bottom`を持たない。
- 旧記事の`div`・`section`・`article`などに付いた`folding`/`supp`クラスは、ビルド時に`details`へ変換し、本文の子要素を`folding-content`へ移す。クラス付きブロック自体を削除してはならない。
- `details.folding`には外枠のborderを付けない。証明本文の`.proof-details-inner.folding-content`が持つ左ガイド線は残す。
- 記事内に明示的な`<details class="folding">`を書く場合は、`<summary>`と本文を必ず含める。
- 記事に折りたたみを足すときは`<div class="folding" data-summary="見出し">`を使い、開始タグと本文の間、本文と閉じタグの間に空行を入れる。空行がないと中身がMarkdownとして解釈されない。
- 定義の本体から独立して読める前提条件（例：「環上の加群の定義」の加法群・係数環・環作用の条件）は折りたたみへ入れる。折りたたみを外して本文へ展開し直さない。

## 図

数学記事の図は次の形にする。

```html
<figure class="math-figure">
  <img
    src="../../../../../images/math/<article>/<file>.svg"
    alt="図が表す内容"
    loading="lazy"
    decoding="async"
  />
</figure>
```

- `alt`は必須で、図の意味を説明する。
- `figcaption`は使わない。レンダラーも数学図内の`figcaption`を出力しない。
- SVG・画像は記事幅とスマホ幅に収まることを確認する。

## 他記事への参照

- 旧記事由来の`[記事タイトル:命題 7]`はレンダラーが同じ言語の公開記事へのリンクへ戻す。
- 参照先の記事がまだ無い場合はリンクにせず、`span.article-reference-pending`として角括弧を外して表示する。角括弧付きの生テキストを本文に残さない。
- リンクが張られない参照が増えたときは、記事タイトルの表記ゆれか、参照先記事が未作成かのどちらかを疑う。

## 回帰チェック

数学記事の組版を変更したときは、少なくとも次を確認する。

1. `npm run check`
2. `npm run lint`
3. `npm test -- --run`
4. `npm run build`
5. `npm run test:e2e -- --grep "数学記事"`
6. `git diff --check`

ブラウザでは「環上の加群の定義」「群の定義」「群の例」「準同型定理」をPC幅とスマホ幅で確認し、定義内の太字、`ol`の番号、証明ボタン、foldingの開閉、図の`alt`、例の外枠なしを確認する。

この規約は、過去に数学記事で記法や折りたたみがCSS・本文変換の変更により失われた再発を防ぐための記録である。
